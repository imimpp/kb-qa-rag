# kb-qa-rag

面向公共服务文档场景的知识库问答系统（RAG）——**当前阶段：工具调用与容错底座 + 文档解析链路 + 三种切块方法对照 + 检索链路定型（混合召回 + Rerank 精排 + MMR 去重）+ 40 题离线评测 + 生成侧带出处问答（命令行链路已跑通）**。

按「先把大模型工具调用、失败处理、安全边界做扎实，再把非结构化 docx 解析成可检索的结构，再向上搭检索与评测，最后接生成侧问答」的顺序推进，每一步的实验数据都记录在 [`实验记录.md`](./实验记录.md) 里，可逐条复现。

> 说明：本仓库当前已完成 **LLM 工具调用底座**、**docx 解析→切块链路**、**三种切块方法对照实验（实验 010）**、**检索链路（向量+BM25 混合召回 → RRF 融合圈候选池 → Rerank 逐块精排 → MMR 压重复，实验 011-013）**、**离线评测（20 题 baseline 扩到 40 题，实验 009/014）** 与 **生成侧带出处问答（命令行链路，出处只列模型实际引用的块，拒答时出处为空）** 六块。切块与检索的**最终选型仍未定**——评测集已扩到 40 题（实验 014），三种切块方法 40/40、38/40、40/40，但递归分隔符那两处失分都带标注区间瑕疵（区间与切块边界错配、封面块擦边命中），不能据此判方法优劣。**当前唯一未达成的收口判据是公网可访问的最小问答页**，详见路线图。没做的绝不标成"已完成"，避免 README 变成简历注水。

## 现在能做什么

### 一、LLM 工具调用底座

一个不依赖任何框架的原生 Function Calling 回路，外加统一的 LLM 客户端封装与七项工程处理：

| 能力 | 实现要点 |
|---|---|
| **工具调用完整回路** | 原生 SDK 手写：JSON Schema 定义 → 模型返回 tool_calls → 本地执行 → `role=tool` 回填 → 二次请求 |
| **表达式安全执行** | 不用 `eval` 裸执行模型输出：`ast` 语法树 + **默认拒绝**白名单（只放行数字与 `+ - * / // % **`），`Call/Name/Attribute` 等一律拒绝 |
| **失败分类处理** | 可重试（超时/限流/连接）走指数退避；不可重试（鉴权/参数非法）零退避立即失败；工具失败原因统一回填给模型，由模型组织话术 |
| **参数校验** | `json.loads` 后校验 dict 类型、必填字段、工具名白名单 |
| **结构化输出** | `chat_json`：请求带 `response_format=json_object` + 客户端 `json.loads` 校验；非法则追加「原文 + 纠错指令」重试 1 次，两次都失败直接抛错，绝不返回半成品 |
| **流式输出** | `stream=True` 增量读取，已测首 token 与完整耗时的 P50/P95 基线（实验 004） |
| **成本账本** | `get_cost()` 按模型累计 token 与金额，区分普通输入 / 缓存命中输入 / 输出单价（实验 006 已逐项核对公式） |

### 二、文档解析链路（第 3 周）

把 43 份医保指南 `.docx` 转成结构化 block，再切成检索用 chunk，全程零 API 调用、零成本：

| 能力 | 实现要点 |
|---|---|
| **docx → block 序列** | `parse_docs.parse_one()` 用 `iter_inner_content()` 按原文顺序遍历段落与表格（`paragraphs`+`tables` 两个独立列表拼接会丢顺序），段落转 `{type,text}`、表格转 markdown，空段落过滤 |
| **合并单元格去重** | Word 横向合并只存一个 `<w:tc>`+`gridSpan`，python-docx 为保「下标=列号」把同一对象多次 yield；**按对象身份 `is` 行内去重**（按文本去重会误删合法重复值），重复位输出空串保住列数（实验 007：填写示范表冗余压掉 78–79%、无合并表 0% 回归干净） |
| **模板占位符隔离** | 四条精确骨架子串匹配把「XXXX年X月X日发布」这类未填模板空位单独收进 `placeholders`，不混入正文 block。对照裸 `X{2,}` 正则**误伤率 72.8%**，是「为什么不用通用正则」的取舍依据（实验 008，43 份全量：隔离 172、残留 0、表格 220/220 未波及） |
| **批量落盘** | `parse_batch.py` 遍历 `data/raw_doc/*.docx` 产出 `data/parsed/*.json`（43 份）；单份失败不拖死整批、末尾汇总；产物带 `source` 字段可溯源 |
| **固定窗切块** | `chunking.chunk_fixed_window()`（默认 500 字符窗口 / 100 重叠）：block 作原子不劈开，累计到窗口封块，把上一块尾部带回做重叠，单独超窗的块独占且不回退尾块；每个 chunk 带 `start:end` 可切回原文。**三种切块方法（固定窗 / 递归分隔符 / 固定窗+大表按行拆）的对照实验已跑（实验 010），并扩到 40 题复测（实验 014）；最终选型仍未定——40 题上 40/40、38/40、40/40 的差距落在两处标注区间瑕疵上，不是方法优劣** |

### 三、检索链路与离线评测

不依赖框架与向量库的「切块 → 混合召回 → 融合圈池 → 精排 → 压重复 → 对标注区间打分」最小实现：

| 能力 | 实现要点 |
|---|---|
| **建索引** | `embed_index.build_index()`：43 份解析 JSON → 切块 → qwen3.7-text-embedding-flash 分批 embed → L2 归一化落盘 `vectors.npy` + `meta.json`（向量行号 ↔ chunk 元数据逐行对齐）；三种切块方法各建一套索引（`data/index/`、`data/index_arm2/`、`data/index_arm3/`） |
| **查询** | `embed_index.search()`：问题向量点积与 BM25（jieba 分词，从 meta 原文现建）两路打分 → RRF 按名次融合圈 top-20 候选池 → qwen3.7-text-rerank 交叉编码器逐块精打分 → MMR 边压重复边挑 5 个（相关项＝rerank 分，多样项＝块间向量相似度）→ 行号回 meta 取原文与出处 |
| **离线评测** | `experiments/exp_009_eval_recall.py`：20 条互联网真实提问、36 个原始 block 答案区间；命中 = 同 source 且区间相交（any-hit 松口径）；问题向量一次冻结落盘、复跑零 embedding API。**固定窗 baseline 冻结口径 Recall@5 = 18/20**（实验 010；早期 19/20 为 live API 抽样）；**检索链路定型后三种切块方法均 20/20 = 1.00**（实验 013，20 题饱和、三方法不可区分，局限见条目）；**扩到 40 题后 40/40、38/40、40/40**（实验 014，旧 20 题零回归，新增 20 题才显出递归分隔符两处失分，且两处均属标注区间瑕疵，局限见条目） |

### 四、生成侧问答（命令行链路）

把检索返回的 5 块原文拼进提示词调 chat，回答带标引、出处可回指原文：

| 能力 | 实现要点 |
|---|---|
| **拼提示词** | `generation.build_messages()`：每块带显式编号、来源文件名与 block 区间；system 约束「只依据给定片段回答」「语料没直答时按固定文案拒答」「示范表里的假身份证、假地址、示范人名不得当真实案例输出」 |
| **出处语义＝实际引用** | `generation.format_answer()`：正文保留标引编号，按编号取对应块生成出处列表（越界编号忽略、重复只列一次）；拒答时出处为空。出处坐标能回指 `meta.json` 原文块 |
| **命令行入口** | `run_qa.py`：串起检索 → 拼提示词 → chat → 打印回答与出处；问题写在文件里 |
| **冒烟验证** | `experiments/smoke_generation.py`：有据代表题与无据题跑一遍，打印检索 5 块、回答、出处回指与机械核对；只验链路通不通，不判断答案语义对错 |

> 生成侧尚未做的部分见「已知限制」：检索层仍含填写示范块（只靠提示词约束挡假数据）、检索命中不等于生成答出、公网问答页未做。

## 快速开始

```bash
# 1. 安装依赖（Python 3.11+）
pip install openai python-dotenv tenacity python-docx numpy jieba rank_bm25

# 2. 配置密钥
cp .env.example .env      # 填入 OPENAI_API_KEY / OPENAI_API_BASE_URL

# 3. 运行工具调用回路
python legacy/function_calling_v2.py

# 4. 解析 docx 语料 → data/parsed/*.json（需本地具备 data/raw_doc/*.docx，该目录 .gitignore 不随仓库分发）
python parse_batch.py

# 5. 建向量索引 → data/index/（调用 embedding API，计费；embed_index.py 的 __main__ 是示例查询，建索引用此命令）
python -c "import embed_index; embed_index.build_index()"

# 6. Recall@5 离线评测（需先建好 data/index/；问题向量读冻结文件，零 embedding API）
python experiments/exp_009_eval_recall.py

# 7. 检索链路定型回归（需三套索引目录；rerank 走 live API，60 次请求，模型版本见实验 013 钉死记录）
#    注意：重跑会覆写 013 落盘证据且 live 分数会漂；要留原证据先改脚本里的输出文件名
python experiments/run_eval_rerank.py

# 8. 命令行问答：检索 5 块 → 拼提示词调 chat → 打印回答与出处（会调 API 计费）
#    注意：问题写在 run_qa.py 里，改问题直接改文件；必须在仓库根运行（索引按相对路径读）
python run_qa.py

# 9. 生成侧冒烟：有据代表题与无据题跑一遍，打印回答、出处回指与机械核对（会调 API 计费）
python experiments/smoke_generation.py

# 可选：复现重试与退避实验（约 5 秒）
python experiments/exp_003_retry.py
```

## 踩坑记录

- **模型给的"安全"不能当安全**：测试 `__import__('os').system('dir')` 时，模型自己就拒绝了执行，端到端看起来"很安全"——但代码层白名单在 4 条端到端用例里一次都没被触发过。真正的拦截能力只能靠单测验证，`calculate()` 的单元测试就是为这个写的。
- **端到端过了不等于代码健壮**：`5×3` 里模型自动把中文乘号归一化成 `5*3`，把 `SyntaxError` 分支掩盖了。所以测试要分两层：端到端测"模型行为"，单测测"代码边界"。
- **`SystemExit` 会杀掉整个进程**：在循环调用 Agent 的函数里写 `raise SystemExit(0)`，第 1 个用例跑完整个程序就退了，后 3 个用例根本没执行。函数内部结束调用只能用 `return`。
- **重试不能一把梭**：把 `AuthenticationError` 也放进重试，会让一个注定失败的请求白等 4 分钟、白烧 4 次配额。分类处理才是正确做法。
- **合并单元格去重只能按对象身份，不能按文本**：python-docx 为守住「下标=列号」的矩形契约，会把横向合并的同一个 `_Cell` 对象连续 yield（表2 某行 12 列里 11 个是同一对象）；但表3 有多个独立单元格合法地同为「是」。按文本去重会误删合法重复值并撑破列对齐，按 `c is prev` 去重才对。
- **遍历 docx 用 `iter_inner_content()`，别拼 `paragraphs + tables`**：后者是两个独立列表，拼起来会丢失段落与表格在正文中的先后顺序。
- **占位符不能用通用正则抓**：裸 `X{2,}` 在 43 份语料上误伤率 72.8%——填写示范表里 `45030519860508XXXX`、`南宁XX贸易公司` 这类合法的脱敏假数据会被全抓进来。只有精确骨架匹配能把"未填模板空位"和"合法 X 数据"分开（实验 008）。

## 已知限制

- 只处理了 `tool_calls[0]`：模型一次要求并行调用多个工具时，历史里会出现"多个 tool_call 只配一条 tool 消息"，下次请求可能 400（待修）。
- `Pow` 未设指数上限：`2**999999` 会卡死（白名单放行，但求值不可控）。
- 仍是"单轮工具调用"：没有多轮循环、没有递归上限。
- `llm_client.py` 的单价表与用量账本目前硬编码了两个模型名，切换未登记的模型会取价失败（待改为未知模型记 0 并告警）。
- `chat_json` 的重试与外层退避叠乘，最坏情况会发出多次真实请求，总次数上限待收敛。
- **切块三种方法已实现并对照，但选型未定**：固定窗 / 递归分隔符 / 固定窗+大表按行拆均已跑通并对照（实验 010），默认窗口/重叠参数（500/100 字符）不代表最终选型；20 题上召回饱和后三种方法不可区分，扩到 40 题虽有 40/40、38/40、40/40 的差距，但失分两题都卡在标注区间口径（区间错配／封面块擦边），不能据此判方法优劣，最终选型继续押后。
- **评测口径偏松、样本仍小**：any-hit＋部分包含算命中，分数是上限；旧 20 题一题即 5 个百分点、≤5 块分层仅 1 题，扩到 40 题后一题 2.5 个百分点、≤5 块分层 4 题；旧 20 题三种切块方法仍全部 20/20 饱和，新增题才显出差距，但差距点在标注口径而非检索能力。**继续扩题／调参都不是当前瓶颈**：生成侧命令行链路已完成，收口判据只剩公网可访问的最小问答页。
- **Rerank 走 live API，复现会漂**：精排模型版本随服务方更新（实验 013 钉死 model id＋日期）；rerank 分为单次请求内相对分，跨请求绝对值比较只作定性观察；score 字段语义自实验 013 起与以前的融合分断代，跨实验引用分数须声明。
- **合并单元格只处理横向**：纵向合并（vMerge）跨行是不同包装对象、markdown 也无 rowspan，故未处理（实验 007 备注②）。单测 `test_parse_docs.py` 目前只覆盖占位符匹配边界（真骨架命中 / 不误伤合法 X 数据），合并去重与空段落过滤尚无独立单测，仅由实验 007（N=1 文档）/ 008（43 份语料脚本核验）覆盖。
- **表2/表3 是否入库尚未决定**：空白表单与填写示范含 `南宁XX贸易公司`、`45030519860508XXXX` 等脱敏假数据，检索命中后有被模型当真实案例输出的幻觉风险（实验 007 备注④）；表1 的 1 列竖排流程图宜转线性文本，延后到切块阶段处理（备注⑤）。
- **生成侧已接上，但检索层仍含示范块**：命令行问答链路（拼提示词调 chat＋标引出处）已跑通，出处能回指 `meta.json` 原文；但填写示范表 / 常见错误示例块按既定口径仍留在检索层，目前只靠提示词约束挡住假数据被当真实案例输出，语料未净化——演示前不得声称已净化，是否整块排除待演示后拍板。
- **检索「命中」不等于生成「答出」，两层口径分开**：40 题评测的命中只要求标注块进 20 块候选池；生成侧只看收窄后送进提示词的 5 块。实测第 46 题（手工报销全额垫付）标注块在池内却未进前 5，送进提示词的 5 块中 4 块是填写示范 / 申报表样本，模型选择拒答而非编造——这是谨慎行为不是错误，记为已知限制。不靠放宽拒答约束或调大 k 硬凑答案；要评估端到端能否答出，须另立生成侧评测，与检索评测分开记。
- **占位符真值是假设不是标注**：实验 008 的"每份 4 条"来自模板结构假设、未经人工逐份标注，漏检不会表现为 FAIL；且仅测大写 `X`，全角 `Ｘ`、小写 `xx`、其它占位字符未审计。
- 复现 007/008 及批量解析需本地具备 `data/raw_doc/` 语料，该目录 `.gitignore`，不随仓库分发。
