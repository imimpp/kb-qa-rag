# kb-qa-rag

面向公共服务文档场景的知识库问答系统（RAG）——**当前阶段：工具调用与容错底座 + 文档解析链路**。

按「先把大模型工具调用、失败处理、安全边界做扎实，再把非结构化 docx 解析成可检索的结构，最后向上搭检索与评测」的顺序推进，每一步的实验数据都记录在 [`实验记录.md`](./实验记录.md) 里，可逐条复现。

> 说明：本仓库当前已完成 **LLM 工具调用底座** 与 **docx 解析→切块链路（固定窗）** 两块，检索（BM25 + 向量 / Rerank）与评测集**尚未开始**。没做的绝不标成"已完成"，避免 README 变成简历注水；切块的三种策略对照实验也还没跑，README 只声明"固定窗切块已实现"，不声称切块方案已选定。

## 现在能做什么

### 一、LLM 工具调用底座

一个不依赖任何框架的原生 Function Calling 回路，外加统一的 LLM 客户端封装与七项工程处理：

| 能力 | 实现要点 |
|---|---|
| **工具调用完整回路** | 原生 SDK 手写：JSON Schema 定义 → 模型返回 tool_calls → 本地执行 → `role=tool` 回填 → 二次请求 |
| **表达式安全执行** | 不用 `eval` 裸执行模型输出：`ast` 语法树 + **默认拒绝**白名单（只放行数字与 `+ - * / // % **`），`Call/Name/Attribute` 等一律拒绝 |
| **失败分类处理** | 可重试（超时/限流/连接）走指数退避；不可重试（鉴权/参数非法）零退避立即失败；工具失败原因统一回填给模型，由模型组织话术 |
| **参数校验** | `json.loads` 后校验 dict 类型、必填字段、工具名白名单 |
| **结构化输出** | `chat_json`：请求带 `response_format=json_object` + 客户端 `json.loads` 校验；非法则追加「原文 + 纠错指令」重试 1 次，两次都失败直接抛错，绝不返回半成品 |
| **流式输出** | `stream=True` 增量读取，已测首 token 与完整耗时的 P50/P95 基线（实验 004） |
| **成本账本** | `get_cost()` 按模型累计 token 与金额，区分普通输入 / 缓存命中输入 / 输出单价（实验 006 已逐项核对公式） |

### 二、文档解析链路（第 3 周）

把 43 份医保指南 `.docx` 转成结构化 block，再切成检索用 chunk，全程零 API 调用、零成本：

| 能力 | 实现要点 |
|---|---|
| **docx → block 序列** | `parse_docs.parse_one()` 用 `iter_inner_content()` 按原文顺序遍历段落与表格（`paragraphs`+`tables` 两个独立列表拼接会丢顺序），段落转 `{type,text}`、表格转 markdown，空段落过滤 |
| **合并单元格去重** | Word 横向合并只存一个 `<w:tc>`+`gridSpan`，python-docx 为保「下标=列号」把同一对象多次 yield；**按对象身份 `is` 行内去重**（按文本去重会误删合法重复值），重复位输出空串保住列数（实验 007：填写示范表冗余压掉 78–79%、无合并表 0% 回归干净） |
| **模板占位符隔离** | 四条精确骨架子串匹配把「XXXX年X月X日发布」这类未填模板空位单独收进 `placeholders`，不混入正文 block。对照裸 `X{2,}` 正则**误伤率 72.8%**，是「为什么不用通用正则」的取舍依据（实验 008，43 份全量：隔离 172、残留 0、表格 220/220 未波及） |
| **批量落盘** | `parse_batch.py` 遍历 `data/raw_doc/*.docx` 产出 `data/parsed/*.json`（43 份）；单份失败不拖死整批、末尾汇总；产物带 `source` 字段可溯源 |
| **固定窗切块** | `chunking.chunk_fixed_window()`（默认 500 字符窗口 / 100 重叠）：block 作原子不劈开，累计到窗口封块，把上一块尾部带回做重叠，单独超窗的块独占且不回退尾块；每个 chunk 带 `start:end` 可切回原文。**注意：三种切块策略的对照实验尚未跑，固定窗目前只是已实现的一个基线，非最终选型** |

## 快速开始

```bash
# 1. 安装依赖（Python 3.11+）
pip install openai python-dotenv tenacity python-docx

# 2. 配置密钥
cp .env.example .env      # 填入 OPENAI_API_KEY / OPENAI_API_BASE_URL

# 3. 运行工具调用回路
python legacy/function_calling_v2.py

# 4. 解析 docx 语料 → data/parsed/*.json（需本地具备 data/raw_doc/*.docx，该目录 .gitignore 不随仓库分发）
python parse_batch.py

# 可选：复现重试与退避实验（约 5 秒）
python experiments/exp_003_retry.py
```

| 编号 | 实验 | 关键结论 |
|---|---|---|
| 001 | 裸调 chat 接口 | 通路验证；`401` 定位靠读报错末行，环境变量名当值是最容易踩的坑 |

## 踩坑记录

- **模型给的"安全"不能当安全**：测试 `__import__('os').system('dir')` 时，模型自己就拒绝了执行，端到端看起来"很安全"——但代码层白名单在 4 条端到端用例里一次都没被触发过。真正的拦截能力只能靠单测验证，`calculate()` 的单元测试就是为这个写的。
- **端到端过了不等于代码健壮**：`5×3` 里模型自动把中文乘号归一化成 `5*3`，把 `SyntaxError` 分支掩盖了。所以测试要分两层：端到端测"模型行为"，单测测"代码边界"。
- **`SystemExit` 会杀掉整个进程**：在循环调用 Agent 的函数里写 `raise SystemExit(0)`，第 1 个用例跑完整个程序就退了，后 3 个用例根本没执行。函数内部结束调用只能用 `return`。
- **重试不能一把梭**：把 `AuthenticationError` 也放进重试，会让一个注定失败的请求白等 4 分钟、白烧 4 次配额。分类处理才是正确做法。
- **合并单元格去重只能按对象身份，不能按文本**：python-docx 为守住「下标=列号」的矩形契约，会把横向合并的同一个 `_Cell` 对象连续 yield（表2 某行 12 列里 11 个是同一对象）；但表3 有多个独立单元格合法地同为「是」。按文本去重会误删合法重复值并撑破列对齐，按 `c is prev` 去重才对。
- **遍历 docx 用 `iter_inner_content()`，别拼 `paragraphs + tables`**：后者是两个独立列表，拼起来会丢失段落与表格在正文中的先后顺序。
- **占位符不能用通用正则抓**：裸 `X{2,}` 在 43 份语料上误伤率 72.8%——填写示范表里 `45030519860508XXXX`、`南宁XX贸易公司` 这类合法的脱敏假数据会被全抓进来。只有精确骨架匹配能把"未填模板空位"和"合法 X 数据"分开（实验 008）。

## 已知限制

- 只处理了 `tool_calls[0]`：模型一次要求并行调用多个工具时，历史里会出现"多个 tool_call 只配一条 tool 消息"，下次请求可能 400（待修）。
- `Pow` 未设指数上限：`2**999999` 会卡死（白名单放行，但求值不可控）。
- 仍是"单轮工具调用"：没有多轮循环、没有递归上限。
- `llm_client.py` 的单价表与用量账本目前硬编码了两个模型名，切换未登记的模型会取价失败（待改为未知模型记 0 并告警）。
- `chat_json` 的重试与外层退避叠乘，最坏情况会发出多次真实请求，总次数上限待收敛。
- **切块只实现固定窗一个基线**：`chunking.chunk_fixed_window()` 已可跑，但三种切块策略的对照实验未做，默认窗口/重叠参数（500/100 字符）尚未经召回验证，不代表最终选型。
- **合并单元格只处理横向**：纵向合并（vMerge）跨行是不同包装对象、markdown 也无 rowspan，故未处理（实验 007 备注②）。单测 `test_parse_docs.py` 目前只覆盖占位符匹配边界（真骨架命中 / 不误伤合法 X 数据），合并去重与空段落过滤尚无独立单测，仅由实验 007（N=1 文档）/ 008（43 份语料脚本核验）覆盖。
- **表2/表3 是否入库尚未决定**：空白表单与填写示范含 `南宁XX贸易公司`、`45030519860508XXXX` 等脱敏假数据，检索命中后有被模型当真实案例输出的幻觉风险（实验 007 备注④）；表1 的 1 列竖排流程图宜转线性文本，延后到切块阶段处理（备注⑤）。
- **占位符真值是假设不是标注**：实验 008 的"每份 4 条"来自模板结构假设、未经人工逐份标注，漏检不会表现为 FAIL；且仅测大写 `X`，全角 `Ｘ`、小写 `xx`、其它占位字符未审计。
- 复现 007/008 及批量解析需本地具备 `data/raw_doc/` 语料，该目录 `.gitignore`，不随仓库分发。
